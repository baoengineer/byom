    How your request changes trains

    Claude Code stays exactly as Anthropic ships it. byoclaude runs a small router on 127.0.0.1 and points Claude Code at it. Each request carries a model ID; the router reads it and sends the request down that model's line.

    • Through serviceProviders that speak Claude's own format. The router swaps the address and key and the request rides through. Claude itself rides on Claude Code's own sign-in, relayed as sent.
    • Change of gaugeOpenAI-style APIs. The router translates messages, tool calls, images and reasoning both ways, so Claude Code never notices.
    • Local lineOllama, LM Studio, or your own server. No account, no data leaves your machine.
    • FallbackIf a model hits a plan limit or is down before it answers, the router tries the next model you listed. Nothing replays mid-answer.

    Claude can change trains too

    Every session loads a small plugin: a skill that tells Claude when another model helps, and one subagent per model. Ask for a second opinion from GPT, a fast pass with a cheap model, or a long read with a million-token context, and Claude sends the work down the right line.

    Claude reads the live roster with byoclaude models --json: each model's subagent, context window, price and whether it is ready or capped.

      Conditions of carriage

      byoclaude is an independent open-source project, not affiliated with or endorsed by Anthropic, OpenAI or any other provider. Each provider's own plan limits and terms apply.

      byoclaude never imitates another app, reads other tools' credentials or pools accounts. It does not offer sign-ins that providers forbid for third-party tools. ChatGPT access uses OpenAI's Sign in with ChatGPT program for open-source apps.

      Claude requests travel on Claude Code's own sign-in, relayed as Claude Code sent them. Anthropic has not explicitly approved relaying subscription traffic through a local proxy, and byoclaude says so on first run. Turn it off with byoclaude config set relay false.
